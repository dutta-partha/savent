The Core Problem: Fragile AI Ingestion

Existing generative AI models can generate network syntax from natural language intents, but they treat YANG data models as flat text. YANG schemas are deeply hierarchical with rich relational constraints (leafref, must, when, choice/case).

Standard RAG workflows dump excessive schema context into the context window, causing:

  • • Configuration Hallucinations: Fabricating non-existent YANG leaves and container paths.
  • • Context Bloat & Waste: Consuming tens of thousands of tokens per simple ACL/VLAN configuration.
  • • Semantic Incoherence: Omitting prerequisite nodes mandated by OpenConfig semantics.
  • • Lack of Pre-Deployment Assurance: Post-deployment monitoring fails to catch invalid push payloads before live outages occur.

The SAVENT Proposition

SAVENT (Schema-Aware Verified Framework for Enterprise Network Configuration) introduces an end-to-end Design Science artifact bridging 4 previously isolated research streams:

1. CUA Compression

Closest Unique Ancestor path pruning minimizes prompt tokens while preserving hierarchy.

2. Schema Hints

Provides concise type, leafref, and value constraints directly to guided decoders.

3. YANG-IR Bridge

Compact intermediate representation deterministically compiled to standard OpenConfig JSON/XML.

4. libyang Validation

Formal yanglint schema verification with an automated error-regeneration feedback loop.

Pre-Deployment Verification Flow

Grounded LLM/SLM decodes intent into compact YANG Intermediate Rep (YANG-IR).

5

Deterministic Transform

Expands compressed paths into full OpenConfig RFC 7951 JSON payloads.

6

Validation Engine

Automated yanglint verification against target schema; feedback loop if error.

Iterative Regeneration Loop

If yanglint emits constraint violations (leafref missing, enum mismatch), the validation error log is injected into the AI Generator prompt for deterministic self-correction (predefined retry budget).

Dual-Track DSR Evaluation

Outputs undergo quantitative metric scoring (SVR, IAS, CHR, RSCS) combined with blinded practitioner evaluation (Appendix C) assessing operational utility.

Evaluation Methodology

Quantitative Metrics & Statistical Protocol

Chapter 3: Inferential Statistics & Non-Parametric Rules
IAS Higher Favorable

Intent Adherence Score

IAS =
∑ Satisfied Atomic Intent Reqs Total Atomic Intent Reqs

Measures atomic requirement alignment. Computed only when valid payload is emitted to avoid scoring non-response as zero.

SVR Higher Favorable

Schema Validation Rate

SVR =
∑ Outputs Passing yanglint Total Evaluation Runs

Proportion of generated network configs strictly conforming to RFC 7950 YANG constraints and data definitions.

CHR Lower Favorable

Hallucination Rate

CHR =
∑ Invalid or Hallucinated Nodes Total Generated Nodes

Quantifies non-existent leaves, containers, or illegal schema paths generated by the underlying language model.

RSCS Lower Favorable

Retrieved Context Size

RSCS =
Tokens in Context Supplied

Measures retrieval efficiency. Lower tokens reduce inference cost, latency, and context degradation without degrading trust.

Inferential Testing Protocol (Table 8 in Proposal)

To ensure methodological rigor, the study avoids ad-hoc statistical assumptions. The 100 enterprise scenarios undergo paired evaluation under identical decoding conditions.

1. Normality Test

Shapiro-Wilk test applied to paired differences (Δ = SAVENT - Baseline). If normal (p ≥ 0.05), report paired t-test; if non-normal, Wilcoxon signed-rank test.

2. Family-Wise Correction

Hypothesis 1 tests (SVR, IAS, CHR) are treated as one hypothesis family for each model. p-values corrected using the Holm-Bonferroni step-down method.

3. Materiality & Effect Size

Predefined practical materiality threshold Δ = ±0.05. Effect sizes reported via Cohen's d (parametric) or Rank-biserial r (non-parametric).
